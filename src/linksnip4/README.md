# LinkSnip

로그인 없이 긴 URL을 6자리 짧은 링크로 변환하고, 짧은 링크 접속 시 원본 URL로 리다이렉트하는 웹 서비스입니다.

제품 요구사항은 [PRD.md](./PRD.md)를 참고하세요.

## MVP To-Do

아래 작업은 의존성 순서대로 정렬했으며, 각 항목은 독립적으로 구현하고 검증할 수 있는 크기로 나눴습니다.

| 작업 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 무료 한도 내 배포 환경과 KV 저장소 선정 | 기술 선택 기록 및 예상 사용량·제약 조건 정리 | 유료 외부 의존성 없이 생성·조회·배포가 가능하며 무료 한도와 제한 사항이 문서에 명시된다. |
| 2. 애플리케이션 프로젝트 초기화 | 실행 가능한 기본 프로젝트, 개발·빌드·테스트 명령 | 새 환경에서 의존성 설치 후 개발 서버, 빌드, 테스트 명령이 각각 성공한다. |
| 3. 환경 변수와 KV 바인딩 구성 | 로컬·배포 환경 설정 예시 및 KV 연결 설정 | 로컬 테스트에서 KV에 테스트 값을 저장한 뒤 같은 키로 조회할 수 있다. |
| 4. URL 유효성 검사 함수 구현 | `http`와 `https`만 허용하는 검증 모듈 및 단위 테스트 | 정상 HTTP/HTTPS URL은 통과하고 빈 값, 잘못된 URL, 그 외 프로토콜은 모두 거부된다. |
| 5. 6자리 코드 생성 함수 구현 | 대소문자·숫자 기반 코드 생성 모듈 및 단위 테스트 | 반복 테스트에서 생성된 모든 코드가 허용 문자로 된 정확히 6자리 문자열이다. |
| 6. 코드 충돌 방지 저장 로직 구현 | 기존 코드 확인 후 재생성하는 KV 저장 함수 및 단위 테스트 | 충돌 코드를 모의 KV에 미리 넣어도 기존 값을 덮어쓰지 않고 새 코드와 URL 매핑을 저장한다. |
| 7. 짧은 링크 생성 API 구현 | URL을 받아 코드와 짧은 링크를 반환하는 엔드포인트 | 유효한 URL 요청은 성공 상태와 6자리 코드·짧은 링크를 반환하고 KV에서 원본 URL을 조회할 수 있다. |
| 8. 생성 API 입력 오류 응답 구현 | 잘못된 요청에 대한 일관된 오류 형식 | 빈 값, 잘못된 URL, 허용되지 않은 프로토콜 요청이 4xx 상태와 사용자 표시용 메시지를 반환한다. |
| 9. 코드 조회 및 302 리다이렉트 구현 | `/:code` 리다이렉트 라우트 | 저장된 코드로 요청하면 상태 코드 302와 원본 URL을 가리키는 `Location` 헤더가 반환된다. |
| 10. 존재하지 않는 코드 오류 화면 구현 | 404 상태의 사용자 친화적 오류 페이지 | 등록되지 않은 6자리 코드로 접속하면 404 상태와 홈으로 돌아갈 수 있는 안내 화면이 표시된다. |
| 11. 잘못된 코드 형식 처리 구현 | 비정상 경로용 오류 처리 | 6자리가 아니거나 허용되지 않은 문자가 포함된 코드는 KV를 조회하지 않고 404 오류 화면을 반환한다. |
| 12. URL 입력 및 생성 폼 UI 구현 | URL 입력란과 “줄이기” 버튼이 있는 메인 화면 | 사용자가 URL을 입력해 제출하면 생성 API가 한 번 호출되며 요청 중 중복 제출이 방지된다. |
| 13. 입력 오류 UI 구현 | 필드 오류 및 서버 오류 메시지 영역 | 잘못된 URL 제출 시 입력란 주변에 이해 가능한 오류가 표시되고 수정 후 다시 제출할 수 있다. |
| 14. 생성 결과 UI 구현 | 생성된 짧은 링크를 보여 주는 결과 영역 | 생성 API 성공 후 응답의 짧은 링크가 클릭 가능한 형태로 화면에 표시된다. |
| 15. 클립보드 복사 기능 구현 | 결과 링크의 “복사” 버튼과 성공·실패 피드백 | 버튼 클릭 시 정확한 짧은 링크가 클립보드에 기록되고 성공 또는 실패 상태가 화면에 표시된다. |
| 16. 반응형 UI 적용 | 모바일·데스크톱 레이아웃 및 스타일 | 320px 너비에서 가로 스크롤이나 겹침 없이 입력, 결과, 오류 화면의 핵심 기능을 사용할 수 있다. |
| 17. 접근성 기본 검증 및 보완 | 레이블, 키보드 포커스, 상태 알림 속성 | 키보드만으로 입력·제출·복사가 가능하고 자동 검사에서 치명적 접근성 오류가 없다. |
| 18. 핵심 사용자 흐름 통합 테스트 작성 | 생성 → 복사 대상 확인 → 리다이렉트 E2E 테스트 | 테스트가 URL 생성부터 반환된 링크의 302 리다이렉트와 원본 목적지 확인까지 자동으로 통과한다. |
| 19. 실패 흐름 통합 테스트 작성 | 잘못된 URL 및 없는 코드 E2E 테스트 | 잘못된 URL의 입력 오류와 존재하지 않는 코드의 404 화면을 각각 자동 검증한다. |
| 20. 응답 성능 측정 및 병목 점검 | 생성·리다이렉트 응답 시간 측정 결과 | 배포 환경에서 대표 요청을 반복 측정했을 때 각 요청의 응답 시간이 1초 이내임을 확인한다. |
| 21. 성공·오류 지표 수집 구성 | 개인정보를 저장하지 않는 생성·리다이렉트 결과 로그 또는 메트릭 | 테스트 요청 후 생성 성공률과 리다이렉트 오류율을 계산할 수 있고 원본 URL은 로그에 남지 않는다. |
| 22. 배포 및 운영 문서 작성 | 배포 절차, 환경 설정, 로컬 실행, 장애 확인 방법 | 문서만 따라 새 환경에 배포한 뒤 링크 생성과 302 리다이렉트를 재현할 수 있다. |
| 23. MVP 출시 점검 | 기능·비기능 요구사항 체크 결과 | F1~F5가 모두 통과하고 생성 성공률 99% 이상, 리다이렉트 오류율 1% 미만, 응답 1초 이내 기준이 확인된다. |

## MVP 제외 범위

- 회원가입 및 로그인
- 커스텀 도메인
- 링크 만료 기능
