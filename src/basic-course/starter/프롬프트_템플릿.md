## P · C · T · F 범용 템플릿 (5.3)

```text
P: <어떤 전문가로서> 작업해줘.
C: 대상은 <파일/모듈>. 제약 — <지켜야 할 규칙 · 금지사항>.
T: <할 일>. 검증 — <통과해야 할 명령/테스트>.
F: <결과 형태 — 변경 파일 목록 · 핵심 3줄 · 실행 결과>.
```

예시 (슬라이드 52)

```text
P: 결제 흐름을 잘 아는 신중한 프론트엔드 개발자로서 작업해줘.
C: 대상은 src/pages/Checkout.tsx 와 src/api/pay.ts.
   제약 — 기존 디자인 토큰만 사용, 새 라이브러리 추가 금지.
T: 결제 실패 시 사용자에게 재시도 버튼을 보여 준다.
   검증 — npm run build 와 npm test 가 통과해야 한다.
F: 변경한 파일 목록과 핵심 변경점 3줄 요약으로 보여줘.
```

## 기법 8가지 (5.7) — 일반형

### 1. 역할 부여

```text
<역할>로서 <대상>을 검토해줘. <관점>의 문제를 심각도(높음 · 중간 · 낮음)와 함께 지적해줘.
```

### 2. 예시 제공

```text
<함수>의 동작을 아래 예시처럼 맞춰줘.
입력: <예1> → 출력: <결과1>
입력: <예2> → 예외: <오류>
이 규칙에 맞는 구현과 테스트를 작성해줘.
```

### 3. 계획 먼저

```text
<기능>을 추가할 거야. 코드를 짜기 전에, 구현을 4~6단계로 나눈 계획과 각 단계의 검증 방법을 먼저 표로 제안해줘.
```

### 4. 제약 · 금지

```text
<파일>만 수정해줘. 제약 — 새 패키지 추가 금지, 공개 함수 시그니처 변경 금지, 다른 파일은 건드리지 말 것.
```

### 5. 가드레일

```text
<질문>. 단, 확인되지 않은 내용은 추측하지 말고 '확인 필요'라고 표시하고, 근거 파일 경로도 함께 알려줘.
```

### 6. 검증 내장

```text
<규칙>을 보장해줘. <테스트 파일>에 테스트를 추가하고, <테스트 명령>을 실행해 전부 통과하는 로그를 마지막에 보여줘.
```

### 7. 출력 형식

```text
결과를 다음 형식으로만 보고해줘. 1) 변경 파일 목록 2) 핵심 변경점 3줄 3) 실행한 명령과 통과 여부. 코드 전체는 다시 붙여넣지 마.
```

### 8. 셀프 리뷰

```text
방금 변경분을 <관점들> 관점에서 셀프 리뷰하고, '항목 / 심각도 / 개선안' 표로 정리해줘. 그다음 심각도 높음 항목부터 고쳐줘.
```

## 자주 쓰는 패턴 (5.9)

| 상황 | 프롬프트 |
|---|---|
| 코드 이해 | <모듈>이 어떻게 동작하고 어떤 모듈이 이를 사용하는지 설명해줘. |
| 버그 수정 | 다음 에러를 재현하는 방법은 <절차>야. 원인을 찾아 고치고, 회귀 테스트를 추가해줘. |
| 리팩터링 | <파일>의 동작은 그대로 두고, 중복을 제거해 가독성만 개선해줘. 테스트가 계속 통과해야 해. |
| 기능 추가 | <옵션>을 추가해줘. 사용법을 README 에도 한 줄 추가하고 예시를 보여줘. |
| 리뷰 요청 | 방금 변경분을 보안 · 성능 관점에서 셀프 리뷰하고 위험 요소를 표로 정리해줘. |

## 치트시트 (부록 A.1)

### 기능 추가

```text
P: 꼼꼼한 프론트엔드 개발자로서 작업해줘.
C: 대상 src/components/Result.tsx / 새 라이브러리 금지, 기존 디자인 토큰 사용.
T: 단축 링크 결과에 "복사" 버튼을 추가. 검증 — npm run build · npm test 통과 + 클릭 시 복사.
F: 변경 파일 목록 + 핵심 변경점 3줄.
```

### 버그 수정

```text
C: 재현 — 빈 URL 입력 후 줄이기 → 앱이 흰 화면이 됨.
T: 원인을 찾아 고치고, 같은 회귀를 막을 테스트 추가.
F: 추가한 테스트가 실패 → 통과로 바뀌는 것을 보여줄 것.
```

### 리팩터링

```text
C: 대상 src/lib/shorten.ts.
T: 동작 / 공개 API는 그대로, 중복만 제거해 가독성 개선.
F: 기존 테스트가 전부 통과함을 보여줄 것(동작 변화 금지).
```

### 계획 먼저

```text
T: 코드를 짜기 전에 5–8개 작은 작업으로 나눈 To-Do만 제안. 각 작업에 "완료 기준" 한 줄씩.
```
