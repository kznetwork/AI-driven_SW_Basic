# hooks-demo — 프로젝트 훅 실습 (읽기 · 기록 · 실행 전 차단)

## 작업 폴더

이 폴더 전체를 `C:\DEV\hooks-demo` 로 복사한 뒤 Codex App 에서 연다.

## 학습 목표

- 훅이 에이전트의 특정 생명주기 시점에 자동으로 실행되는 스크립트임을 설명한다.
- 프로젝트 범위의 `.codex/hooks.json` 을 읽고 이벤트별 실행 시점을 구분한다.
- 신뢰 확인 후 `SessionStart` · `PostToolUse` 실행 결과를 직접 확인한다.
- `PreToolUse` 훅으로 위험한 명령을 실행 전에 검사하고 차단한다.

## 처음 들어 있는 훅

| 이벤트 | 역할 | 확인 방법 |
|---|---|---|
| `SessionStart` | 새 세션 또는 재개 시 검증 규칙을 컨텍스트로 전달 | 새 채팅을 열고 상태 메시지 확인 |
| `PostToolUse` | 도구 실행 뒤 이벤트·도구 이름만 JSONL 로 기록 | `.codex/hooks/events.jsonl` 확인 |

`PreToolUse`(차단 훅)는 **처음에는 없다.** 수업에서 프롬프트로 직접 만든다 (prompts.md 4 ~ 8번). 완성본은 `참고\` 에 있다.

## 참고\ 폴더

| 파일 | 내용 |
|---|---|
| `hooks.json` | PreToolUse 가 추가된 완성본 |
| `pre_tool_use_guard.ps1` | Windows 용 차단 스크립트 (영어 전용) |
| `pre_tool_use_guard.py` | Python 판 — 같은 규칙 |
| `course.rules` | 7장 Rules 예시 (`prefix_rule`, BOM 없는 UTF-8) |
| `시험_명령표.md` | 두 스크립트에 15개 명령을 넣어 시험한 결과 |

## 주의

- 프로젝트 훅은 신뢰한 프로젝트에서만 실행된다. 처음 로드할 때 검토와 신뢰가 필요하다.
- 훅 스크립트는 내 PC 에서 실행된다. 내용을 읽어 보지 않은 훅은 신뢰하지 않는다.
- 훅이 오류 · 시간 초과로 끝나면 명령이 그대로 실행될 수 있다 — 훅은 Sandbox · 승인과 함께 쓰는 안전망이다.
- 훅 로그에는 이벤트와 도구 이름만 남긴다. 프롬프트 · 파일 내용 · 도구 인수 전체는 기록하지 않는다.
