# 실습 프롬프트 — ToDo
9장 PRD 작성 · To-Do 도출 — 할 일 관리 앱
교안: `(교안) Codex App(데스크톱웹)을 활용한 소프트웨어 개발 기본 과정_v3.pptx` · 작업 폴더: `C:\DEV\ToDo`

## 어디에서 실습하나 (작업 폴더)

| 항목 | 내용 |
|---|---|
| 작업 폴더 | `C:\DEV\ToDo`  (macOS: `~/DEV/ToDo`) |
| 방식 | **새로 만들기** — 빈 폴더 `C:\DEV\ToDo` 를 직접 만든 뒤 Codex App 에서 **'폴더 열기'**(또는 프로젝트 만들기 → 소스 폴더)로 연다. 이 제공 폴더(`ToDo\`)는 **열어 보는 용도**다 — prompts.md 의 프롬프트를 복사하고, 막힐 때만 `참고/` 와 비교한다 (작업 폴더로 복사하지 않는다). |
| 해당 교안 절 | 9장 9.1 · 9.2 |

## 쓰는 법
- 작업 폴더 `C:\DEV\ToDo` 를 새로 만들고, **Codex App 에서 '폴더 열기'(또는 프로젝트 만들기 → 소스 폴더)** 로 연다.
- 이 파일을 VS Code 나 메모장에 열어 두고, 코드 블록을 복사해 **Codex 작성 칸**에 붙여 넣는다.
- `@경로` 는 파일을 컨텍스트에 넣고(작성 칸에서 `@` 입력 후 검색), `/명령` 은 앱 · CLI 명령이다.
- 승인 창이 뜨면 **무엇을 하려는지 읽고** 허용한다. 네트워크가 필요하면 '이번에만 허용'.
- 기대 결과는 요약이다 — **응답 문구와 코드 모양은 실행마다 다르다.** 판단 기준은 파일 · 화면 · 명령 실행 결과다.

## 9장 · 9.1

### 할 일 관리 앱 PRD 작성 요청
<sub>슬라이드 115 · 9장 · 9.1</sub>

```text
할 일 관리 앱을 만들고 싶어. PRD를 작성해줘.
매일 10-20개 정도의 할 일을 관리하는 개인용 앱이야.
주요 기능은:
- 할 일 추가, 수정, 삭제
- 완료 체크 기능
- 카테고리 분류 (업무/개인/공부)
- 진행률 보기
브라우저에서 바로 실행되고, 새로고침해도 데이터가 사라지지 않았으면 좋겠어.
기술적으로 복잡하지 않게 순수 자바스크립트로 만들고 싶어.
```

**기대 결과(요약)** PRD 초안(한 줄 요약 · 목표 · 시나리오 · 기능 · 비기능 · 범위 제외 · 성공 기준). 파일로 저장하려면 'PRD.md 로 저장해줘' 를 덧붙인다.

### PRD 확인과 다듬기 — 빠진 것을 질문으로 채운다
<sub>슬라이드 116 · 9장 · 9.1</sub>

```text
@PRD.md 를 읽고 (수정하지 말고) 빠진 항목이나 모호한 표현을 5개 이내로 질문 형태로 알려 줘.
내가 답하면 그 내용을 PRD.md 에 반영해 줘.
단, '범위 제외' 절에는 이번 MVP 에서 만들지 않을 것을 반드시 적어 줘.
```

## 9장 · 9.2

### PRD 로부터 실행 가능한 To-Do 를 도출해 README.md 로
<sub>슬라이드 117 · 9장 · 9.2</sub>

```text
@PRD.md 이 PRD를 읽고 할 일 관리 앱 MVP를 완성하기 위한 실행 가능한 To-Do를 만들어 README.md 파일을 작성해줘.
규칙:
- 각 작업은 독립적으로 구현하고 테스트할 수 있는 작은 단위로 나눌 것
- 각 항목마다 "완료 기준"을 작성할 것
- 작업 간 의존성을 고려하여 구현 순서대로 정렬할 것
- 너무 많은 기능을 한 Task에 묶지 말 것
- 가능하면 테스트 작업을 각 구현 단계와 함께 포함할 것
- 다음 형식의 표로 정리할 것: Task | 산출물 | 완료 기준
```

**기대 결과(요약)** README.md 에 `Task | 산출물 | 완료 기준` 표 (Task 이름 · 개수는 실행마다 다르다)
