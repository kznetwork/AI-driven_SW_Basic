## 프로젝트 개요

- 비밀키/토큰을 코드에 하드코딩하지 말 것. 환경변수를 사용한다.
## PR(풀 리퀘스트) 규칙
- 커밋 메시지는 한 줄 요약 + 변경 이유로 작성한다.

## 8장 · 8.9 — 루프 · 모델 엔지니어링

### 루프 실습 ① — 일부러 깨고, 통과할 때까지 반복시킨다
<sub>슬라이드 109 · 8장 · 8.9</sub>

```text
shorten.ts 의 makeCode 가 5자리를 반환하도록 일부러 바꿔 줘 (실습용으로 깨는 것이다).
그다음 아래 루프를 실행해 줘:
1) npm test 실행
2) 실패하면 로그를 읽고 원인을 고친다
3) 다시 npm test 실행

규칙:
- 모두 통과하면 멈추고, 시도 | 실행 결과 | 고친 내용 표로 정리해 줘
- 3번 시도해도 통과하지 않으면 멈추고 이유를 보고해 줘 (무한 반복 금지)
- tests/ 폴더의 파일은 수정하지 말 것
```

**기대 결과(요약)** 실패 → 수정 → 재실행 → `2 tests passed` 와 시도 표. 응답 문구 · 시도 횟수는 실행마다 다르다.

- 확인: 로그에서 '실행 → 실패 → 수정 → 재실행' 읽기  ▸  마지막에 npm test 통과  ▸  tests/ 가 바뀌지 않았는지 확인
